# كيف نقيّم الاستراتيجيات ونختار الأفضل

## الخطة المقترحة (3 مراحل)

### 1) باك تست (Backtest) — دقائق
بنشغّل كل البوتات على بيانات تاريخية حقيقية من باينانس:
```bash
python main.py backtest --days 365
python main.py backtest --start 2022-01-01 --end 2022-12-31   # سوق هابط
python main.py backtest --start 2023-10-01 --end 2024-03-31   # سوق صاعد
```
**مهم:** جرّب على فترات مختلفة (صاعد / هابط / عرضي). استراتيجية بتنجح بفترة وحدة بس، غالباً حظ.

### 2) Paper Trading — أسابيع
كل البوتات بتشتغل مع بعض على الأسعار الحية بفلوس وهمية:
```bash
python main.py run
python main.py report      # من terminal ثاني بأي وقت
```
الهدف نتأكد إنه النتائج الحية قريبة من الباك تست (ما في أخطاء أو مفاجآت).
**أقل شي 2–4 أسابيع**، والأفضل لحد ما كل بوت يعمل 20–30 صفقة على الأقل.

### 3) Testnet ثم Live — بمبلغ صغير
بس للاستراتيجية (أو الاستراتيجيتين) اللي فازوا. شوف [README](../README.md#التحويل-لـ-live).

## شرح أعمدة جدول المقارنة

| العمود | المعنى | شو بدنا |
|---|---|---|
| `Return%` | الربح/الخسارة الكلي | أعلى |
| `Market%` | حركة سعر العملة نفسها بنفس الفترة | للمقارنة |
| `MaxDD%` | أكبر نزول من قمة رأس المال لقاعه | **أقل** — هاد قديش رح "توجعك" |
| `Ret/DD` | الربح ÷ أكبر تراجع | **أهم رقم.** فوق 1 منيح، فوق 2 ممتاز |
| `Sharpe` | الربح مقابل التذبذب (سنوي) | فوق 1 منيح |
| `Trades` | عدد الصفقات المكتملة | أقل من 20 = النتيجة مش موثوقة إحصائياً |
| `Win%` | نسبة الصفقات الرابحة | مش لحاله مهم! (Breakout بيربح بـ 35%) |
| `PF` | Profit Factor = مجموع الأرباح ÷ مجموع الخسائر | فوق 1.3 منيح، تحت 1 خسران |
| `AvgTrade%` | متوسط ربح الصفقة بعد الرسوم | لازم يكون أكبر بوضوح من 0.2% (الرسوم) |
| `Fees` | مجموع الرسوم المدفوعة | إذا كبير مقارنة بالربح → كثرة صفقات |
| `InMkt%` | نسبة الوقت اللي البوت كان داخل فيه | أقل = مخاطرة أقل |

## معايير الاختيار النهائي

اختار الاستراتيجية اللي:
1. **بتربح بأكثر من فترة** (صاعد + عرضي على الأقل، وما بتنهار بالهابط).
2. `Ret/DD` أعلى من Buy & Hold.
3. `PF > 1.3` و `Trades >= 20`.
4. نتيجة الـ Paper قريبة من نتيجة الباك تست.
5. **ما تكون حساسة كثير للمعاملات**: إذا `sma 20/50` بتربح بس `18/50` و `22/50` بتخسر، هاد Overfitting. الاستراتيجية المنيحة بتشتغل منيح على مجموعة قيم قريبة.

## تحذيرات مهمة
- **Overfitting:** لا تضل تغيّر المعاملات لحد ما الباك تست يطلع حلو — رح يطلع حلو عالماضي بس. عدّل بالمعاملات على فترة، وجرّب النتيجة على فترة ثانية ما استخدمتها.
- **الأداء الماضي لا يضمن المستقبل.**
- الباك تست بيفترض التنفيذ على سعر إغلاق الشمعة + slippage 0.05% + رسوم 0.1%. الواقع ممكن يكون أسوأ شوي.
- ما في استراتيجية بتربح بكل الأوقات. ممكن بالنهاية تختار استراتيجيتين مختلفتين (وحدة اتجاه ووحدة ارتداد) يكمّلوا بعض.

## الفريم الزمني والرسوم
كل صفقة كاملة (شراء + بيع) بتكلّف حوالي **0.3%** (رسوم 0.1% × 2 + slippage). على فريم الساعة البوتات بتعمل 100–300 صفقة بالسنة، يعني الرسوم لحالها ممكن تاكل 30% أو أكثر من رأس المال.
قارن نفس البوتات على أكثر من فريم:
```bash
python main.py backtest --days 365 --interval 1h
python main.py backtest --days 365 --interval 4h
python main.py backtest --days 365 --interval 1d
```
(مع `--interval` اسم كل بوت بالجدول بيصير `name@4h` مثلاً.)

## فلتر الاتجاه العام (`trend_filter_ema`)
إعداد بيتطبّق على **أي** استراتيجية: البوت ما بيفتح صفقة جديدة إلا إذا سعر الإغلاق فوق EMA(N) لنفس فريم البوت. الخروج ما بيتأثر، بيضل حسب الاستراتيجية والـ stop loss.
```yaml
- name: supertrend_4h_filter
  strategy: supertrend
  interval: 4h
  trend_filter_ema: 200     # على 4h = اتجاه آخر ~33 يوم، على 1d = آخر 200 يوم
```
الفكرة: البوتات اللي بتشتري وبتبيع بس (Long-only) ما بتقدر تربح من الهبوط، فأحسن شي إنها ما تدخل أصلاً وقت السوق هابط. بباك تست 2022 (السوق −64%)، `ema_trend` اللي فيها هاد الفلتر خسرت −15% بس.
الثمن: بتفوّت أول الصعود بعد القاع، لأنها بتستنى السعر يرجع فوق المتوسط.

## تجربة نسخ مختلفة من نفس الاستراتيجية
بالـ `config.yaml` فيك تضيف نفس الاستراتيجية أكثر من مرة بأسماء مختلفة:
```yaml
- name: supertrend_10_2
  strategy: supertrend
  params: {period: 10, multiplier: 2.0}
- name: supertrend_10_3
  strategy: supertrend
  params: {period: 10, multiplier: 3.0}
- name: supertrend_10_3_tp
  strategy: supertrend
  params: {period: 10, multiplier: 3.0}
  take_profit_pct: 8
```
